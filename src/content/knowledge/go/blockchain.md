**区块链（Blockchain）**是一种特殊的数字数据存储技术，可以简单理解为：一个由很多计算机共同维护、公开透明、难以篡改的分布式账本。

## how work

```txt
传统银行会把这些交易记录保存在银行自己的数据库里。

而区块链的做法不同：

记录交易：把发生的交易记录下来。

打包成区块：将一段时间内的交易打包成一个数据块（Block）。

验证交易：由网络中的多个节点共同验证。

连接区块：每个区块通过密码学哈希值与前一个区块关联。

共同保存：网络中的多个节点保存账本副本。
```

- 如果一家公司的财务记录只保存在自己的电脑里，公司可以自行修改记录。

- 但如果记录保存在区块链上，由多个节点共同维护，那么想要偷偷修改历史记录就会困难得多。

## 区块链：去中心化模式

- 你向区块链网络发起转账。

- 网络中的节点收到交易信息。

- 节点根据规则验证交易。

- 网络通过共识机制确定哪些交易被记录。

- 节点更新各自保存的账本。

## 公示机制

> 工作量证明PoW 权益证明PoS

- PoW：通过计算竞争记账。

- PoS：通过质押资产参与验证。

## 区块链为什么不需要银行？

银行的核心作用：**中心化第三方，负责记账、担保、核验转账，解决 “两个人互不信任，谁先给钱” 的信任问题**。
区块链用**密码学 + 分布式共识机制**替代了这个第三方角色：

- 转账不再由银行一台中心服务器单独记账；
- 交易由全网节点共同验证签名、交易合法性；
- 达成共识后写入账本，规则写死在代码里，不需要一个机构单独说了算；

## 为什么很多计算机可以共同记账？

依靠**分布式账本 + 共识机制**：

1. 每一台参与的计算机（节点），本地都保存一份完整（或部分）账本副本；
2. 所有节点遵守同一套共识规则（PoW/PoS/PBFT 等）；
3. 产生新交易后，节点互相广播交易信息；
4. 大家按照统一规则，一起验证交易、选出下一个区块；
5. 验证通过的区块追加到链条上，同步给所有节点，**所有诚实节点最终账本保持一致**。
   简单说：大家提前约定好一套统一的校验 + 选块规则，按规则同步，就能一起记账。

## 区块链的数据为什么不容易修改？

三个核心原因：链式哈希、多副本、修改成本极高

1. **链式哈希绑定**：每个区块保存自己的哈希，同时记录上一个区块的哈希。一旦改动区块里任意一点点数据，本区块哈希立刻变化，后面所有区块的哈希全部失效。想让修改生效，就要重新计算这个块之后**全部区块**。
2. **多节点副本**：账本不是存在一台电脑，成千上万个节点都存了副本。只改自己一台机器上的数据没有用，其他节点不认。
3. **共识门槛约束**（PoW 举例）：想要修改历史数据并让全网承认，必须掌握绝大多数算力，重新挖出一条更长的分叉链替换主链，也就是 51% 攻击。
   ✅ 关键结论：**不是绝对不能改，是修改的代价非常高，经济上很难实现**。
   如果恶意节点达不到多数算力 / 权益，修改会直接被其他节点拒绝。

## what hash algorithm

```txt
哈希算法是一个单向、固定输出长度的数学函数，随便输入一段数据，算出一个独一无二、长度固定的摘要（哈希值）。
输入：hello
SHA256: 2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824
```

**单向性（最重要）**
只能：原始数据 → 算出哈希
**不能：哈希值反推回原始数据**
你拿到上面那串 64 位字符，没有办法反向算出原文是 hello。

# 挖矿（PoW 工作量证明）

> 挖矿是 PoW 共识里矿工通过不断尝试随机数，计算满足难度条件的哈希，竞争区块记账权的过程。矿工负责收集、校验交易并打包上链；成功挖出区块的矿工获得代币奖励。算力代表计算哈希的能力，算力越高挖到区块概率越大。
> 一句话：
> **挖矿就是节点反复试随机数，算出一个满足规则的哈希，抢到打包区块的资格；成功抢到的节点，获得出块奖励。**

1. **打包交易，维持账本持续更新**
   交易不会自己上链，矿工负责收集、校验交易，打包成区块，追加到区块链。
2. **PoW 的共识机制：用算力竞争，决定谁有记账权**
   不是投票、不是身份优先，谁先算出符合条件的哈希，谁获得本轮记账权。

- 算力 = 计算哈希的速度。算力越高，抢先试出合法 nonce 的概率越大。

## sha-256

- SHA：Secure Hash Algorithm，安全哈希算法
- 256：输出固定 **256 bit（二进制）** 的哈希值

写成十六进制就是 **64 个字符**，就是我们平时看到那一长串：

```md
1. **输入任意大小**：几个字、一个文件、整个区块都可以
2. **输出永远固定 256 位**
3. **单向不可逆**：哈希值不能反推原文
4. **雪崩效应**：原文改 1 个字符，哈希完全变样
5. **抗碰撞**：很难找到两份不同数据算出同一个 SHA256

## 比特币里的两个核心用途（重点，和挖矿挂钩）

1. **区块指纹**
   区块头做 SHA-256，得到区块哈希；下一个区块头存上一个区块哈希，串成链，用来检查篡改。

> 比特币是做两次 SHA-256：`SHA256(SHA256(区块头))`，俗称双 SHA256

2. **PoW 挖矿的计算函数**
   矿工不断改 nonce，反复对区块头算双 SHA256，直到结果满足难度条件（前面有 N 个 0）。挖矿本质就是疯狂跑这个函数试随机数。
```

# 公钥 & 私钥（非对称加密）

> 公钥和私钥是非对称密钥对，私钥保密，用于对交易签名；公钥公开，用于验证签名。公钥无法推导出私钥。
> 一句话：**一对钥匙，私钥自己保管，公钥公开；私钥用来签名，公钥用来验签。**

- 私钥：只有你自己知道，**绝对不能泄露**。可以生成签名，代表 “是我本人授权这笔交易”。
- 公钥：可以公开对外分发。别人拿到公钥，只能验证签名是不是私钥签出来的，**不能反推出私钥**。

交易流程：
你用私钥对转账交易签名 → 交易全网广播 → 其他人用你的公钥校验签名 ✅

> 核心：**私钥 = 身份控制权，谁持有私钥，谁就拥有这个地址里的币**。

## 私钥为什么如此重要？

私钥是地址资产的唯一凭证：
转账必须用私钥签名；只有私钥才能生成合法签名。
一旦私钥泄露，任何人都可以冒充你签名转走你的币；私钥丢了，谁也帮你恢复，资产永久无法动用。公钥只是用来验签，没有控制权。

## 数字签名

> 数字签名使用私钥对数据哈希摘要签名，其他人用对应公钥验证；用来证明数据来源、防止数据被篡改、发送方无法否认。
> **数字签名 = 用私钥给一段数据打上 “不可伪造的身份戳”**

> 流程：

1. 对交易数据先算哈希摘要
2. 使用私钥加密这个摘要，得到【签名】
3. 交易 + 签名一起发出去
4. 接收方用发送者公钥解开签名，对比原始数据哈希：一致 = 签名有效

三大作用：

1. **身份认证**：确认是私钥持有人发的
2. **防篡改**：交易改一个字节，哈希变了，签名校验失败
3. **不可抵赖**：签了就是你签的，没法否认

# 区块之间如何连接

一句话：**靠上一个区块的哈希值串联，形成链式结构**
每个区块头里面存放：
`本区块交易根哈希 + 时间戳 + nonce + 【上一个区块的哈希】`

链路：
`区块0哈希` → 放在区块 1 头部
`区块1哈希` → 放在区块 2 头部
`区块2哈希` → 放在区块 3 头部

一旦修改某个区块内部交易：
本区块哈希改变 → 下一个区块记录的 “上块哈希” 对不上 → 链条断裂，诚实节点直接识别篡改。

> 后一个区块的区块头保存前一个区块的哈希值，把区块依次串联；修改任意区块数据都会改变它的哈希，导致后面链条校验失败。

## 智能合约

**智能合约是部署在区块链上、满足条件就自动执行的一段代码**，一旦上链，无法随意篡改，执行不需要第三方中介。

> 本质：区块链上的可执行程序。

```md
1. 写在链上（以太坊主流语言：Solidity），部署后地址固定；
2. **事件触发、自动执行**：if 条件满足 → 自动跑逻辑；
3. 代码公开可验证（公链），结果记录进区块，不可抵赖；
4. 只能做链上能做的事：转账、代币发放、修改合约内数据；**不能主动访问互联网（没有外部 HTTP 请求）**，需要预言机（Oracle）拿外部数据。

### 例子

众筹合约：达到筹款金额，自动打款给项目方；超时没达标，自动退款给参与者。
```

# Gas 费用是什么

> 以太坊（EVM）里的概念

**Gas 是执行智能合约、转账等操作消耗的计算单位；Gas 费是给矿工 / 验证者的酬劳**。

- Gas：衡量计算工作量（加减、存储、调用合约都消耗不同 Gas）
- Gas Price：每个 Gas 的单价，单位 gwei
- 总费用公式：

\(\text{Gas费} = \text{GasUsed} \times \text{GasPrice}\)

## Merkle树

> Merkle 树是一棵哈希二叉树，叶子节点是原始数据块的哈希，非叶子节点是它两个子节点哈希拼接后再算哈希；根哈希（Merkle Root）可以一次性校验一大批数据有没有被篡改、有没有丢块。

1. **篡改检测**
   只要任意一块原始数据改了 → 对应叶子哈希变 → 一路向上所有父哈希全部变化 → **根哈希一定变**。只需要对比根哈希就能知道这批数据有没有被改。
2. **Merkle Proof（默克尔证明）—— 最强特性**
   不用下载全部数据，**只需要一小串 “兄弟哈希”，就能证明某一条数据确实在这个集合里**。
   例子：上面树里，想证明「数据 1 存在」，只需要给验证方：`H2、H34`。验证方自己算出 H1 → 算出 H12 → 算出 H1234，和公布的根对比。
