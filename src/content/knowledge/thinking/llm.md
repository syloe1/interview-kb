# LLM / RAG / Agent / ToolCall 笔记

LLM 有理解能力但没有记忆，需要靠驱动的函数、上下文窗口实现记忆。
大模型应用里，一切是上下文的流动。

- Prompt：你对模型的指令
- Messages：模型里“带状态的”对话消息数组
  - System Message：设定人设、全局规则
  - User Message：用户的提问
  - Assistant Message：模型返回的回答
- Context Window：模型一次能启动、处理的最大 Token 数量；超过这个限制，模型会遗忘前面内容
- Token：模型最小处理单位
- Stream：流式输出，像打字机一样，一个词一个词吐出

## ToolCall 工具调用

给模型一套工具说明（例如 get_weather 函数）。
模型根据用户需求判断：我不知道天气，但我可以调用。
模型**并不执行代码**，它只返回一个“我要调用函数”的指令；由代码去真正执行。

## RAG 检索增强生成

RAG 相当于给模型带了一本额外的参考书。
流程：

1. 用户提问
2. 去向量数据库检索相关文档
3. 把文档片段 + 用户问题一起塞给模型
4. 模型结合文档回答

## Agent 智能体

把检索、工具调用、组装、调用、排序、控制，做成自动化流水线。
Agent 有自主规划能力：给它一个目标，它会自动思考第一步做什么、第二步调用什么工具。
